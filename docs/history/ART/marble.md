**Status:** Implemented; status reconciled and regression-tested 2026-07-23.
**Owner once approved:** Codex executes from this spec.
**Reviewer:** project owner.

## Goal

Add a reusable **marble** material primitive (procedural texture + Three.js material) to the babel scene. Marble is the prestige stone for future open-world structures (collapsed temple façades, cloister columns). It is NOT being applied to the existing tower — the tower stays canon as weathered limestone shell + scorched basalt plinth.

This spec ships the material primitive plus a development-only preview cube (gated behind `?preview=marble`) so the visual can be verified before any structure consumes the material. Column drums, prestige-building placement, and the burn-overlay system are out of scope; each gets its own follow-on spec.

## Texture pipeline

Procedural `THREE.CanvasTexture`, generated at runtime. Mirrors the existing `createTowerTextures` pattern in [src/scene/textures.js](src/scene/textures.js). New function: `createMarbleTextures(qualityProfile)`.

**Outputs** (one CanvasTexture each):

- `colorMap` — marble face. Base `marbleBase` fill, organic vein traces, occasional darker cracks, soft polished-sheen highlight.
- `bumpMap` — subtle relief on veins only. Marble is polished; bump is much weaker than limestone's mortar-driven bump.

**Vein generation algorithm:**

1. Generate **8 / 12 / 16** vein paths (low/balanced/high tier) using a Perlin or simplex noise field. Each vein wanders across the canvas with smooth curvature — **no grid pattern, no straight lines**.
2. Stroke each vein as a curve with `globalAlpha: 0.18`, color `marbleVein`, line width `1.5–3 px` (jittered per vein).
3. Add **2–4** darker "cracks" with `marbleShadow`, alpha `0.32`, slightly thicker stroke (3–5 px) and longer paths than veins.
4. Apply a soft radial gradient highlight: center at canvas midpoint, color `marbleHighlight`, alpha `0.12`, falloff to transparent at the edges. This mimics polished sheen.
5. Final pass: 1 px Gaussian blur to soften the painterly look (canvas-2d `filter: 'blur(1px)'` on a temp canvas, then drawn back).

The bumpMap is generated by:

1. Render the same vein paths in greyscale (white veins on black background, alpha 1.0, no highlight).
2. No cracks (cracks are color-only, not relief).
3. No final blur (bump should be crisp).

**Canvas sizes:**

| Tier     | Size        |
| -------- | ----------- |
| Low      | 256 × 256   |
| Balanced | 512 × 512   |
| High     | 1024 × 1024 |

Larger than tower's tier sizes (which are vertical strips for a cylinder); marble panels are square-tileable.

**Texture properties:**

- `wrapS`/`wrapT`: `THREE.RepeatWrapping`
- `colorSpace`: `THREE.SRGBColorSpace` (apply via `setSrgbTexture` helper at the top of [src/scene/index.js:25-33](src/scene/index.js#L25-L33))
- `anisotropy`: use the existing `chooseAnisotropy(min, max)` helper in [src/scene/index.js](src/scene/index.js) — `chooseAnisotropy(2, 8)` is appropriate.

## Material configuration

Single `THREE.MeshStandardMaterial`, factory function `createMarbleMaterial(textures)`:

- `color`: `0xffffff` (let the texture carry the color)
- `map`: marble colorMap
- `bumpMap`: marble bumpMap
- `bumpScale`: `0.05` (subtle — marble is polished)
- `roughness`: `0.35` (moderately polished, not mirror)
- `metalness`: `0.05` (slight specular bounce)

Export via `scene.createMarbleMaterial = createMarbleMaterial` for consumers in future specs.

## Preview placement

A single development-only preview cube, gated behind a URL parameter. NO production impact.

- **URL trigger**: `?preview=marble` in the page URL. Read via `URLSearchParams(window.location.search)`.
- **Geometry**: `THREE.BoxGeometry(4, 4, 0.5)` — a roughly door-sized panel.
- **Position**: `(15, 6, 0)` — east of the tower, eye-level for the dev-mode character. Visible from the orbital camera too.
- **Rotation**: `Math.PI / 2` around Y so the wide face points back at the tower (visible from the orbit).
- **Material**: the new marble material.
- **Parent**: appended directly to `homeScene` (not to any tower group).

The preview cube is added at the end of `initHomeScene` after all tower assembly. If `preview !== "marble"`, no cube is added and the scene is unchanged.

## Tests

1. `MARBLE_PALETTE is frozen and exposes the documented tokens` — assert `Object.isFrozen` true, assert each of the four expected keys is present and is a 7-char hex string starting with `#`.

## Verification criteria

After Codex implements, the spec is satisfied when ALL of these hold:

1. `npm run verify` passes.
2. `npm test` passes; test count goes from 74 → 76.
3. `npm run build:dist` succeeds. Scene bundle stays under the 810 kB budget enforced by [test/bundle-output.test.mjs](test/bundle-output.test.mjs).
4. `npm run preview` then load `http://127.0.0.1:4173/?preview=marble`. Expect:
   - A single pale cool-grey cube ~15 ft east of the tower, eye-level.
   - Cube faces show wandering organic veins (no grid pattern, no straight lines).
   - Cube reads distinctly from the limestone tower — cooler, paler, slight polished sheen.
5. Enter dev mode (backtick), walk to the cube, get close. Veins resolve as soft painterly traces, not pixelated edges.
6. Reload without `?preview=marble`. Cube is absent; tower scene is unchanged from current.

## Out of scope (each gets its own spec)

- **Column drums** — cylinder geometry sharing this material; separate spec because the geometry is different.
- **Prestige-building placement** — putting marble onto an actual structure (e.g., the collapsed temple). Future spec; depends on this material existing.
- **Burn overlay / scorch staining** — affects all stones, not marble-specific. Decal system applied additively over any base stone material.
- **Carved relief / capitals** — high-relief decoration. Future spec; likely needs imported geometry (GLTF), not procedural.
- **Vein variants** (stripes, brecciated, statuary white) — single subtle veined style only for v1. Variants are easy follow-ons.
- **Texture imports refactor** — keeping the procedural canvas pipeline for now. If we later decide to use authored marble textures, that's a separate spec.

## Followup specs (rough order)

1. `ART/burn-overlay.md` — soot/scorch decal system, distance-falloff anchored to the tower's collapse zone. Uses scrolling-texture-minus-grayscale-gradient additive-blend technique for active fire embers in the burn zone.
2. `ART/marble-column-drum.md` — cylinder geometry for column shafts, consuming `createMarbleMaterial` from this spec.
3. `ART/asset-imports.md` — refactor to optionally use imported textures (the standing. `fantasy_ps1` library). Marble texture can be upgraded from procedural to authored at that point.
